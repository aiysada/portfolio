# PROMPT 07 — Indie Sign Quote History and Document Archive

## 1. Role and Objective

Act as a senior React, TypeScript, and local-first application engineer.

Continue the existing Indie Sign project.

Inspect the current implementation and integrate with:
- Price Calculator.
- Shared quote and pricing models.
- PDF document generation.
- Owner Settings.
- Centralized LocalStorage data utilities.
- JSON backup and restore.

Implement a reliable Quote History system for saving, viewing, searching, and regenerating documents.

Do not rebuild the application or remove existing features.

Do not add a backend, external database, customer accounts, or cloud synchronization.

## 2. History Page

Create a dedicated Quote History page accessible from Owner Settings.

Use a clear, responsive table on desktop and suitable cards on mobile.

For each saved record, show:
- Quote/document number.
- Creation date.
- Item summary.
- Total amount in LAK.
- Available document types.
- Last updated date, if relevant.

Provide actions to:
- Open details.
- Regenerate a PDF.
- Delete a record after confirmation.

Do not add a dashboard or statistics section.

Do not implement job statuses or payment tracking.

## 3. Save Quotes

Add a clear Save Quote action to the Price Calculator.

When the owner saves a quote:
- Validate the quote data.
- Generate or assign a unique local record ID.
- Preserve the document number when one already exists.
- Save a complete snapshot of the quote.
- Save all item descriptions, dimensions, units, quantities, unit prices, fees, discounts, tax settings, and totals.
- Save the pricing configuration needed to reproduce the original calculation.
- Save document settings relevant to the generated document.
- Record creation and update timestamps.

Avoid accidental duplicate records from repeated clicks.

If the quote has already been saved, offer to update the existing record or save a separate copy.

Make the behavior clear to the user.

Do not automatically save incomplete or invalid quotes.

## 4. Data Snapshot and Historical Accuracy

This is a critical requirement.

A historical quote must preserve the original:
- Product name and description.
- Material name.
- Dimensions and units.
- Quantity.
- Unit price.
- Line subtotal.
- Design fee.
- Labor fee.
- Installation fee.
- Delivery fee.
- Extra service charges.
- Discount.
- Tax percentage and amount, if applicable.
- Grand total.
- Document terms and relevant settings.

Changing product prices or owner settings later must not change historical quote totals.

Regenerating a historical PDF must use the saved snapshot rather than current product prices or current calculator defaults.

If the logo or font asset is no longer available, display a clear warning rather than silently generating a misleading document.

For regenerated documents, distinguish between:
- Reprinting the saved document.
- Creating a new document based on updated details.

Do not silently overwrite a historical document when creating a new version.

## 5. Customer Data Minimization

Do not create a customer database.

Do not save customer details for automatic reuse in future quotes.

If customer name or phone is required for a document, keep it only in the corresponding quote/document record when the owner explicitly saves that record.

Do not save unsaved customer form data automatically to history.

Allow the owner to delete a history record and its associated customer information.

Explain that saved records remain in the current browser until deleted or browser data is cleared.

## 6. Search and Filtering

Provide search by:
- Document number.
- Item or service description.
- Customer name only within saved records.

Provide filters for:
- Date range.
- Document type where relevant.

Sort by:
- Newest first by default.
- Oldest first.
- Document number.
- Total amount.

Include:
- Clear search.
- Empty-state instructions in Lao.
- Useful no-results feedback.
- Pagination or a performant list if the record count becomes large.

Do not introduce a search feature to the public Portfolio page.

## 7. Quote Details

When opening a history record, show:
- Document number.
- Creation date.
- Saved line items.
- Original dimensions and units.
- Original prices and fees.
- Discount and tax breakdown.
- Original total.
- Saved customer details, if any.
- Saved notes and terms.
- Available document types.

Provide a clear Back to History action.

Display a notice explaining that the record is a historical snapshot and does not automatically update when product prices change.

## 8. PDF Regeneration

Allow the owner to regenerate available document types from the saved quote snapshot.

Requirements:
- Reuse the existing PDF generation system.
- Preserve the original amounts.
- Preserve the original item descriptions.
- Preserve the saved customer information.
- Preserve document settings relevant to the original record.
- Keep Lao text rendering correct.
- Support download and print.

Do not require the owner to recreate the quote manually.

Do not fetch current product prices to calculate historical totals.

If a user intentionally wants updated pricing, create a separate new quote using the current calculator and label it as a new quote.

If the document numbering system is already implemented, reuse it and prevent accidental duplicate numbers.

## 9. Edit and Delete Behavior

Allow limited editing of saved record metadata where appropriate, such as internal notes.

If any financial field is edited:
- Make the change explicit.
- Recalculate only through a controlled quote-edit workflow.
- Preserve the original snapshot or revision history where practical.
- Never silently modify a previously issued document.

Before deleting a record, show a confirmation dialog that identifies the record.

Delete only the selected record and its associated stored data.

Do not delete unrelated documents or application settings.

## 10. LocalStorage Integration

Integrate history into the existing versioned local-data schema.

Requirements:
- Use the centralized data layer.
- Use stable record IDs.
- Handle malformed or missing stored records safely.
- Preserve history during normal application initialization.
- Avoid duplicate writes.
- Handle storage quota errors gracefully.
- Keep the UI synchronized after save, update, restore, and delete.
- Preserve compatibility with JSON backup and restore.

Update the JSON backup system so that it exports all saved history and can restore it after schema validation and explicit confirmation.

Do not include active authentication sessions or plaintext PIN values in backups.

If restoration fails, retain the existing valid data.

Do not assume LocalStorage data is synchronized between devices.

## 11. Document Numbering

Reuse the existing numbering utilities.

Use the existing prefixes and date-based sequence format for:
- Quotations.
- Invoices.
- Receipts.

Do not create a second independent numbering mechanism.

Preserve original document numbers when reprinting historical documents.

If the owner generates a new document, allocate a new number when appropriate.

Allow manual number editing only through the existing validated document workflow.

## 12. User Experience

Use the existing Indie Sign design system:
- Lao interface.
- Orange accent.
- Light and dark themes.
- Responsive layout.
- Clear loading, success, and error states.
- Confirmation dialogs for destructive actions.
- Accessible controls.

Display monetary values consistently in LAK.

Provide a visible warning in the history section:

Saved history is stored in this browser. Export a JSON backup regularly before clearing browser data or moving to another device.

Do not show customer information in unnecessary list views beyond what is useful for identification.

## 13. Testing Requirements

Add tests and verify:
1. Saving a valid quote creates one history record.
2. Repeated save clicks do not accidentally create duplicate records.
3. Search by document number works.
4. Search by item description works.
5. Date filtering works.
6. Opening a record shows the saved snapshot.
7. Updating product prices does not change historical totals.
8. Regenerated PDFs use saved prices.
9. Deleting a record removes only that record.
10. JSON backup includes history.
11. Restoring a valid backup restores history.
12. Invalid backup data does not overwrite valid records.
13. Lao text and LAK formatting remain correct.
14. Mobile and dark-mode layouts work.
15. The production build passes.

Run the available tests and build commands. Fix errors introduced by this step.

Do not claim that a test passed unless it was actually executed.

Report in Lao:
- Files created or modified.
- History features implemented.
- Snapshot strategy.
- PDF regeneration behavior.
- Backup and restore integration.
- Actual test results.
- Production build status.
- Known limitations.

Stop after implementing Step 7. Do not begin the next phase automatically.
